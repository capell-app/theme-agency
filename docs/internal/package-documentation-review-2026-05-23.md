# Package Documentation Review - 2026-05-23

This review tracks the full package documentation rebuild. Code, manifests, config, routes, providers, migrations, Actions, and tests remain the source of truth.

## Acceptance Criteria

Every package should have:

- a README linked from the repository docs index;
- a workflow-value section that explains why the package helps a Capell owner, editor, developer, or operator;
- a clear ownership boundary;
- runtime surfaces linked or named from real code;
- package docs linked from the README;
- related package links where the package naturally fits a workflow bundle;
- focused verification commands;
- no stale package catalog or legacy extension language unless it is documenting an actual current surface.
