# Using Experiments

This guide is for owners and operators who run A/B tests. Every step uses the labels you see on screen.

## What you're looking at

| Screen or signal | What it tells you |
| --- | --- |
| **Experiments** | Your tests and whether they are running |
| **Variants** | The versions being compared |
| **Traffic percentage** | How many visitors each variant gets |
| **Winner** | The variant that performed best |

## What to do when...

| Situation | What to do |
| --- | --- |
| You want to test a change | Create an experiment with the current page and the new variant |
| Results look close early on | Wait; results aren't reliable until enough people have seen both |
| One variant is clearly ahead | Once enough visitors have taken part, pick the **Winner** |
| You're not getting enough traffic | A/B testing needs volume; consider testing a higher-traffic page |

## Settings and retention

- Set the **traffic percentage** so the test reaches enough visitors without disrupting everyone.
- Don't call a winner too early. Let the test run until the result is stable.
