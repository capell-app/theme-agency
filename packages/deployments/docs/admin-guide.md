# Using Deployments

This guide is for owners and operators who watch releases. Every step uses the labels you see on screen.

## What you're looking at

| Screen or signal | What it tells you |
| --- | --- |
| **Deployment Repository** | The list of releases |
| **Status** | Whether a release succeeded or failed |
| **Failed** | A release didn't complete |
| **Dry run** | A check of a release without applying it |

## What to do when...

| Situation | What to do |
| --- | --- |
| The latest release succeeded | Nothing to do |
| A release shows **Failed** | Tell your developer and share what the status shows |
| You're unsure a change went live | Check the latest release status here |
| A release is mid-way | Wait for it to finish before making more changes |

## Settings and retention

- This is mostly a status view for owners. The technical detail of a failure is for your developer.
- Use a **dry run** to check a release safely when that option is offered.
